# 虚拟参赛：单场参考表现分

日期：2026-09-08。状态：本地实现与专项验收通过；未推送、打包或替换安装版。

## 用户契约

虚拟参赛可以计算个人本场参考表现分，但不能改变总体平均表现、最佳表现、平均排名或正式 Rating。参赛场次数仍计入虚拟训练次数，不等于将其分数纳入总体评估。

基线：虚拟场次只有提交与复盘，没有参考分。当前方案：增加独立 `virtualReference`，已结束场次随复盘自动计算，在列表中与正式比赛同列、同色阶显示，不需展开详情或点击计算。保留详情重算入口；正式字段 `performance`、`officialRank`、`ratingDelta` 保持为空。总体统计再按正式 CONTESTANT 身份硬过滤，防止异常字段误入统计。

## 数据和计算

1. 从 Codeforces 获取该场完整 standings（包含非正式参赛）与原比赛 ratingChanges；沿用已有请求队列，不增加登录或 AI 请求。
2. 虚拟成绩必须精确对应账号、VIRTUAL 身份与此次 startTimeSeconds；拒绝团队、幽灵以及重复匹配。比赛与本次虚拟时间窗必须已经结束，成绩必须 FINAL、未冻结，支持 CF/ICPC，暂不支持 IOI。
3. 仅使用原比赛 Rated 选手作为对照，每位必须有完整最终榜单数据。剔除用户自己曾经正式参加该场的记录；至少保留两名有效对照选手。
4. 将这一次虚拟的官方榜单 points/penalty 插入对照组，以现有 Carrot 排名及零增量表现分算法计算单场参考分；不直接使用包含其他非正式选手的榜单 rank。同分同罚时沿用 Carrot 的并列末位排名口径。
5. 用户锚定 Rating 取虚拟开始前最近一次有效历史 Rating；缺少时使用 1400 并明确提示。算法区间到达边界时显示 ≥6000 或 ≤-500，不能解释成精确能力分。

这是“如果把这次成绩放入原比赛 Rated 人群，会得到怎样的参考表现”的模拟，不是 Codeforces 颁发的新 Rating。历史对手强度、虚拟赛条件、Hack 机制以及已练过题都会影响可比性。当前榜单可能因后续重判或取消资格而不同于当时 Rating 排名，不能声称复现原始结算；本次没有进行真实样本预测误差校准。

官方字段依据：[API Objects](https://codeforces.com/apiHelp/objects)、[contest.standings](https://codeforces.com/apiHelp/methods#contest.standings)。不从本地题数臆造官方得分；找不到可靠的本次榜单成绩时明确不可用。

## 保存、展示与失败边界

- 每个 replayId 独立存放结果、方法版本、对照人数、锚定来源、计算时间和提交指纹；重复虚拟不共享分数。
- 提交指纹变化使旧参考分失效；写入前校验账号、同步版本和场次指纹，避免旧请求覆盖新数据。
- 重启可读缓存；重算失败时保留仍有效的上次结果并标明更新失败；首次失败显示原因，不生成假分数。
- 列表和详情显示本场参考分；无结果时区分待计算、暂不可用，不再统称“不计分”。详情明确非官方及排除总体统计。已知赛前 AC 时显示练过题提醒；本地历史不完整时无法保证识别所有已练习题。
- 自动调度先完成正式复盘及元数据，再处理已结束、没有缓存结果的虚拟场次。失败结果缓存并停止自动重试，避免轮询请求风暴；可在详情显式重试。已有旧失败缓存的场次需要手动重试一次。
- AI 复盘上下文将此字段标明 official:false、excludedFromOverall:true，不伪装成官方数据；未调用付费服务。
